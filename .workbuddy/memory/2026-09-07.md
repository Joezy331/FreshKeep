# 2026-09-07

## 鲜存 FreshKeep 微信小程序 MVP（从 0 搭建完成）

- 技术栈：微信小程序原生 + TypeScript + WXSS，零第三方依赖；开发者工具靠
  `useCompilerPlugins: ["typescript"]` 编译 .ts，不需要 npm install。
- 项目根：`E:\codex_projects\Freshkeep`，AppID 用测试号即可跑。
- 架构约定（重要）：
  - `services/ai/` 只做识别，业务层只调 `recognizeImage()`；换真实视觉模型
    只需实现 `VisionProvider` 并在 `services/ai/index.ts` 里 `setProvider()`。
  - `services/food/fridge.ts` 是唯一数据出入口（get/set 封装），后续上云只改这里。
  - 状态计算统一在 `services/food/expiration.ts`（URGENT_DAYS=1 / SOON_DAYS=3）。
  - WXML 模板里**不能**调用 `indexOf/map/filter/join`，需要的数据一律在 .ts 里
    预计算成 data（曾在 profile 页踩坑，已改为 `dislikeMap` / `initial`）。
- 演示数据：`data/demo.ts` 8 种食材，日期按 today 动态计算（菠菜/豆腐 1 天 urgent、
  西红柿 2 天 soon），首次启动写入 `fk:seeded` 标记。
- 本地脚本：`tools/gen_icons.py`（纯标准库生成 81×81 TabBar PNG，环境无 Pillow）、
  `tools/smoke.mjs` + `tools/resolver.mjs`（Node ESM 无扩展名 import 钩子，
  用 `node --experimental-strip-types --import` 跑核心逻辑冒烟测试）。
- 已通过校验：JSON 合法性、app.json 页面/图标存在、组件声明、事件 handler 定义、
  WXML 标签配对、TS 语法、核心链路冒烟（识别→入库→分区→提醒→推荐→消耗）。
- 待办/下一阶段见 README 第 7 节（真实视觉模型、云开发、家庭共享、订阅消息、浪费账单）。
