## 修复：逻辑流程图「排版对齐 + 居中」（同文件 735540142556778）

### 问题定位（用 capture_layout 拿坐标分析）
- 根因：**三分支那一层（正常/临期/已过期）横向展开后宽 1648px，超出 1240px 画布** → fork 溢出到 `x=-204`，左右各溢出 204px，整体无法居中。
- 次要：外层 fork 左右两列宽度不等（616 vs 272），导致视觉重心偏移（中心 448 / 620 / 964，不对称）。

### 修复做法
**重新生成 HTML 并覆盖导入**（调整容器宽度不会让 absolute 定位的导入节点重新居中，必须重新导入）：
1. `.wrap` 宽度 1240 → **1440**（容纳最宽行 1312px）
2. 统一节点宽度：处理节点 280px、判断菱形 220×110
3. 修正 HTML 的 `margin:0 auto` 造成的 x=240 偏移
4. 流程：`D("3:1")` 删旧帧 → 重新 `register_assets` + curl PUT + `html_to_ardot(pageId="0:1")` → 新帧 `9:1`
5. 收紧：`U("9:2",{x:0,y:0})` + `U("9:1",{width:1440,height:2863})`，**消除导入器产生的 1920 宽 / 240px 左右留白**

### 结果
- 画布 **1440×2863**（原 1920×2862 带 240px 留白）
- `capture_layout(problemsOnly:true)` 在 `9:2` 内部返回**空数组** —— 溢出/重叠/零尺寸全部消除
- 标题 / 主干 / 各分支 / 图例全部严格居中
- 预览图：`preview/keepfresh-logic-flow.png`（1440×2863，101.7 KB）

### 关键经验（复用）
- **判断分支横向展开是最容易撑爆画布的地方**：必须先算最宽行 = Σ(列宽) + Σ(gap)，画布宽度 ≥ 最宽行 + 2×padding。本图最宽行 = 280+56+624+56+280 = 1312（中间「临期」列因含嵌套 fork 而宽 624）。
- **导入后外层容器会被撑到 1920 宽**：固定套路是 `U(外层, {width: 实际宽, height: 实际高})` + 若内容有 `margin:auto` 偏移则 `U(内容帧, {x:0,y:0})`。
- **改容器宽度不会重排已导入的 absolute 节点** —— 布局要变必须改 HTML 重新导入。
- 排查对齐问题的高效方式：`capture_layout` 拿各节点的 `bounds.x` + `width`，算中心点是否等于容器中心（如 1240/2=620），一眼看出偏移。

## 修复：逻辑流程图「方框内文字居中 + 统一」（同文件 735540142556778）

### 问题定位（batch_read 拿每个 text 节点的 textAlignHorizontal / x / width）
- 表面看所有 text 节点 `textAlignHorizontal` 都是 `CENTER`，但**居中失效**——因为节点的**定位**不对：
  - **带副文案的高框**（如 9:14）导入时生成了内部 flex 包裹帧（`layout:"vertical"` + `counterAxisAlignItems:"CENTER"`），所以这类框文字**已经居中**。
  - **单行框 / 胶囊 / 菱形 / AI 框**的文字是**绝对定位**的直接子节点，`x` 被导成「框中心值」当**左边缘**用（如 9:76 x:140 在 280 框里 → 文字从中心往右铺）。长文案甚至溢出：`计算保鲜周期与建议食用日期`（x:140 + 宽 169 = 309 > 280）。
- 菱形文字在内部帧（9:23 等）里，内部帧本身居中于菱形（中心≈110），但文字在帧内 x 偏移 → 看着偏右。

### 修复做法（batch_edit，21 个 U()）
对每个偏移的 text 节点统一设：
`{width:<所在容器满宽>, x:0, textAlignHorizontal:"CENTER", textAlignVertical:"CENTER"}`
- 单行框/胶囊：width = 280 / 172
- 菱形：width = 内部帧宽（155.5 / 130.5 / 168 / 180.5），因内部帧已居中于菱形
- AI 框副文案帧（9:42/9:186）先设 `{width:280, x:0}` 再设文字居中

### 二次修复：AI 框 tag 与标题重叠
把标题居中后与左上角英文 tag（`Vision Recognition · Baidu AI Cloud`）**同行重叠**。修复：
- 合并被导入拆成两行的标题（9:40「百度智能云菜」+ 9:41「品识别」→ 合并为「百度智能云菜品识别」，`D("9:41")`）
- tag 上移到 `y:3`（9:38）/ `y:1`（9:183），标题下移到 `y:24` / `y:18`，副文案再下移，形成「tag 置顶 + 标题居中 + 副文案居中」的干净三行

### 关键经验（复用）
- **html_to_ardot 导入 text 时，`x` 是绝对左边缘**；HTML 里靠 `text-align:center` 视觉居中的单行文字，导入后左边缘会落在框中心 → 必须显式 `width`(满宽) + `x:0` + `textAlignHorizontal:"CENTER"` 才是真居中。
- 有副文案的框会生成 flex 包裹 → 自动居中；单行框不会。**别只看 textAlignHorizontal，要连 x/width 一起看**。
- Ardot 文字横向/纵向对齐属性是 `textAlignHorizontal` / `textAlignVertical`（值 LEFT/CENTER/RIGHT、TOP/CENTER/BOTTOM），不是 `textAlign`。
- 校验顺序：`capture_screenshot(9:1)` 看整体 → 缩放到具体分区（如 9:25 / 9:121）看细节；1px 级文字溢出可忽略（≤4px 容差）。
