# 2026-09-30

## 修复「流程图打不开」——Ardot 画布过重导致浏览器卡死

### 现象
用户反馈 9-29 晚交付的 v1 切割版（fileId `730954968877481`）**打不开**。

### 排查
1. 先验证本地 PNG 预览图完好性 —— 4 张 PNG 的 IEND 尾块全部 OK，**不是图片损坏**。
2. `fetch_editor_state` 显示文件可访问、结构正常 —— **不是文件失效**。
3. 定位到真因：**画布被撑爆**。9-29 那次切割我把 `7:22` 放大到 `2720×2900`，又把整个根帧复制一份做「备份」堆在**同一画布**，导致：
   - 画布总尺寸达 **6000×3311**
   - 节点数翻倍（原始 ~340 + 备份副本）
   - 浏览器打开时渲染卡死/超时

### 修复（关键手法）
**把备份移出主画布 → 独立分页**，主画布只留一份内容：
1. `create_new_page(name="★ v1 原始备份（2×2 单页版）", select:false)` → 得到 `28:1`
2. `M("17:1", "28:1")` —— 备份副本移到新页（备份仍在，但不再拖累主画布）
3. `M("17:343", "7:22")` + `M("17:394", "7:22")` —— 总览/图例收进切割版容器（原先散落在 page 顶层、坐标错乱）
4. 收紧切割版布局：`7:22` 改为 `1330×2080`；4 个画板重新疏排 01(0,0)/02(704,0)/03(0,800)/04(704,800)；总览(0,1600)、图例(0,1810)

### 结果
- 主画布 **2720×2900 → 1330×2080，面积减少 62%**
- 顶层节点回归单一 `7:1`，不再横向堆叠
- 截图验证正常渲染：`preview/keepfresh-flow-split-preview.png`（1330×2080，102.8 KB）
- 旧的大图 `keepfresh-flow-parts-split-preview.png`（6000×3311）已删除

### 经验教训（重要）
- **Ardot 做「备份」不要在同一画布复制根目录**，会让节点翻倍导致文件打不开。正确做法：`create_new_page` 建独立备份页 + `M()` 移过去，主画布保持轻量。
- 画布宽度建议控制在 ~1400px 内；超大拼接画布即使服务端能截图，客户端浏览器也可能加载失败。
- 「文件打不开」的排查顺序：PNG/IEND 完整性 → `fetch_editor_state` 可达性 → **画布尺寸与节点量**（最常见的真因）。
- `batch_read` 返回的深层 `children` 会被截断成字符串 `"..."`，且 TEXT 的 `content` 可能缺失 —— **不能依赖它做完整内容提取/重建**。
