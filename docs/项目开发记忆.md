## 一、项目概览

FreshKeep 是一个**微信小程序原生 + TypeScript + WXSS** 的「AI 智能冰箱管家」产品，零第三方运行时依赖。核心能力：拍照/手动录入食材 → 百度智能云菜品识别 → 智能保存建议 → 冰箱库存管理 → 临期提醒 → AI 食谱推荐 → 食材消耗闭环。

- **本地运行**：开发者工具靠 `useCompilerPlugins: ["typescript"]` 编译 `.ts`，无需 `npm install`。AppID 用测试号即可跑。
- **架构约定**（关键）：
  - `services/ai/` 只做识别，业务层只调 `recognizeImage()`；换真实视觉模型只需实现 `VisionProvider` 并 `setProvider()`。
  - `services/food/fridge.ts` 是唯一数据出入口（get/set 封装），上云只改这里。
  - 状态计算统一在 `services/food/expiration.ts`（`URGENT_DAYS=1` / `SOON_DAYS=3`）。
  - WXML 模板**不能**调用 `indexOf/map/filter/join`，需预计算成 `data`。
- **诚实标注原则**（贯穿全程）：百度菜品识别=真实接入；AI 食谱=`Recipe Recommendation Prototype`（本地规则匹配，`services/recipe` 无 LLM 调用）；保存建议=Rule-based（food-database 规则库，未包装成 AI）。所有设计稿均标注此边界，未虚构能力。
- **安全红线**：全程未触碰任何百度 Key/Secret；曾硬编码的密钥已移出仓库（仍须到控制台轮换，见第四节）。

## 四、经验沉淀（跨日志汇总，可直接复用）

### 微信小程序
1. **禁止在 barrel 文件转发类型**（`export type { X }` 不带 from 且 X 未 import → 单文件编译当运行时具名导出 → 整页白屏）。业务页尽量直接 import 叶子模块；遇「某几个页面同时白屏」先按 import 依赖分组找共同依赖。
2. **禁止 `await import()` 动态导入**，一律顶部静态 import。
3. **WXML 内联 style 一律写完整声明 + 结尾分号**（否则 `css-semicolongexpected`）。
4. **WXML 模板不能调用 `indexOf/map/filter/join`**，需预计算成 `data`。
5. **`wx.chooseMedia` 必须由用户点击手势触发**，不能 onLoad 自动调起；失败降级 `wx.chooseImage`，权限拒引导 `wx.openSetting`。
6. 改代码**一律用 Edit/Write**，不要 bash 拼字符串写文件（双引号会被 bash 吃掉）。
7. 脚本批改后**立即 grep 复核选择器名与实际一致**。

### Ardot 设计（html_to_ardot 路径）
8. **复杂流程图用「Write 自包含 HTML → create_design → register_assets → curl PUT（COS 预签名）→ html_to_ardot → capture_screenshot」最高效且高度还原**，比手工 batch_edit 摆 100+ 节点省大量 token。
9. **导入后外层容器会被撑到 1920 宽**（若 HTML 有 `margin:auto` 还会偏移）→ 固定套路 `U(外层,{width:实际宽,height:实际高})` + `U(内容帧,{x:0,y:0})`。每次导入后都该检查。
10. **html_to_ardot 导入单行 text 时 `x` 是绝对左边缘**（HTML `text-align:center` 的视觉居中导入后左边缘落框中心）→ 必须显式 `width:满宽` + `x:0` + `textAlignHorizontal:"CENTER"` + `textAlignVertical:"CENTER"` 才是真居中。**别只看 textAlignHorizontal，要连 x/width 一起看**。
11. 对齐属性是 **`textAlignHorizontal`/`textAlignVertical`**（LEFT/CENTER/RIGHT、TOP/CENTER/BOTTOM），**不是 `textAlign`**。
12. **判断分支横向展开最易撑爆画布**：先算最宽行 = Σ(列宽)+Σ(gap)，画布宽 ≥ 最宽行 + 2×padding。
13. **`.page{border-bottom:2px dashed}` 之类会被转成 `Line` 且 height=0 → ZERO_SIZE error「node will be invisible」**，用 `D()` 删零尺寸 Line 修复（视觉零变化）。
14. **`C()` 复制无法跨文件**；Ardot **无「删除整个文件」接口**，只能 `D("根帧")` 清空内容（壳需 UI 手动删）。
15. **「备份」不要同画布复制根目录**（节点翻倍 → 文件打不开）。正确：`create_new_page` 建独立备份页 + `M()` 移过去，主画布保持轻量；画布宽控 ~1400px 内。
16. `capture_layout(problemsOnly:true)` 读法：**只有 ZERO_SIZE/OVERLAP/CLIP 才动手**；`LARGE_EMPTY_AREA`（留白意图）/`OUTSIDE_PARENT`（导入副产物）属预期非缺陷。`capture_layout` 必填 `fileUrl`+`parentId`，结果过大时落盘到 tool-results，用 Bash+Python 正则统计 `"code"`/`"severity"` 分布来读。
17. `capture_screenshot` 是稀缺资源：每修复批次最多 2 次（通常 1 次），所有待验证节点一次传入；避免宽/高 >2000 的节点（超则拆分区截）；1px 级文字溢出可忽略（≤4px 容差）。
18. `batch_read` 深层 `children` 会被截断成 `"..."`，TEXT 的 `content` 可能缺失 → 不能依赖它做完整内容提取/重建。

### 工程 / 安全
19. **沙箱 git push 失败**（代理屏蔽 `github.com:443`）时改用 **GitHub Git Data API**（`gh api` 走 `api.github.com`：Contents API 种初始 commit → blobs→tree→commit→PATCH refs）。本地与远端哈希不同，用户本机需 `git reset --hard origin/main` 对齐。
