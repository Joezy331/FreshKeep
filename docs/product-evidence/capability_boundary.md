# FreshKeep 能力边界声明（Capability Boundary）

> 目的：明确区分"真实 API / Mock / 规则推荐 / 逻辑层提醒 / 真实推送 / 真实用户数据"，防止把演示能力包装成已验证能力。
> 适用：简历、面试、作品集、汇报。凡标注 ⚠️ 的项不得写成"已实现/已验证"。

---

## 一图速记

- **真实已验证（规则层）**：保鲜计算、保存建议、库存批次、菜谱规则推荐、消耗扣减、提醒逻辑生成。
- **真实代码但未端到端验证**：百度菜品识别 API 调用。
- **Mock / 可插拔兜底**：视觉 Provider 的 Mock 与 LLM 降级。
- **仅逻辑层、未触达用户**：临期提醒。
- **仅为计划 / 设计**：订阅消息推送、浪费复盘、云端埋点、真实用户实验。
