## B. 各竞品事实依据与来源

1. **Samsung Family Hub / AI Vision Inside**
   - 事实：内置摄像头，AI Vision Inside 可识别约 33 种生鲜（放入/取出时识别），生成食物清单；可手动设 use-by 日期；Samsung Food App 按现有食材推荐个性化菜谱；2026 升级引入 Google Gemini 增强识别与 OCR 识别包装商品。
   - 来源：https://www.samsung.com/au/family-hub-refrigerator/ ；https://samsung-newsroom-production.barbariangroup.com/us/samsung-expands-ai-capabilities-bespoke-ai-family-hub-refrigerators-major-update
   - 支持度：官方页面直接支持。

2. **LG InstaView ThinQ**
   - 事实：29" 透明触控屏 + 内部广角摄像头，可远程查看内容；推荐基于冰箱内已有的菜谱；可手动设食物过期日期； Alexa 语音引导做菜。
   - 来源：https://www.lg.com/uk/lg-magazine/what-is-new/smart-fridge-ifa-2019-instaview
   - 支持度：官方页面直接支持。**注意**：LG 的"识别"主要是摄像头查看，并非自动视觉识别录入（与 KeepFresh 的"拍照识别录入"不同）。

3. **下厨房**
   - 事实：国内老牌菜谱社区（北京瑞荻互动），300 万+ 实测菜谱；支持"输入冰箱食材反向匹配菜谱"、合并购物清单、时令推荐。**但它本质是菜谱社区，不做冰箱库存/临期管理。**
   - 来源：https://www.pc6.com/az/1705343.html ；https://blog.xiachufang.com/page/37
   - 支持度：官方/下载站直接支持。结论"非库存管理"为本人判断（基于功能描述）。

4. **薄荷健康**
   - 事实：综合健康管理 App；「薄荷 AI 相机」一拍餐食知重量/热量/营养；自研 FoodNet v4 图像模型，中餐高频菜品识别准确率 91.7%（来源标注为第三方测评口径）；2025 推出大模型减重模型；拍照识别接入百度开放平台，识别 1000+ 菜肴需会员。
   - 来源：https://boohee.com/ ；https://www.oppozhijia.com/wz/1066673.html ；https://m.toutiao.com/article/7634060853221884462
   - 支持度：官方+媒体直接支持。准确率数字来自媒体测评，**非本人测试**，引用须注明"第三方测评口径"。

5. **FridgePal**
   - 事实：iOS 食材库存 App；**小票拍照自动解析入库**；冰箱/冷冻/常温分区 + 数量 + 颜色新鲜度点；预估过期日 + 临期提醒（到期前2天/当天/后1天可设）；可手动添加。
   - 来源：https://apps.apple.com/cn/app/fridge-pal-grocery-tracker/id6783085449
   - 支持度：App Store 商品页直接支持。

## C. 竞品分析结论

**公开资料直接支持的事实：**
- 家庭食材管理的主流形态分两类：**硬件派**（三星/LG，靠冰箱内置摄像头，重硬件、贵、识别类别有限）与 **软件派**（FridgePal 小票入库、薄荷健康拍照识别、下厨房反向搜菜谱）。
- "拍照/小票识别 → 库存 → 临期提醒 → 按库存推荐菜谱"是已被验证的需求链路，多家产品独立印证。
- 临期提醒与"按现有食材推荐菜谱"是高频共性卖点。

**本人产品判断（非公开资料直接支持，仅供参考）：**
- 现有竞品普遍**重"识别/记录"、轻"闭环引导"**：录入后如何尽快消耗、识别失败如何兜底，体验割裂。
- 硬件派门槛高、软件派（FridgePal/薄荷）在国内微信生态渗透弱；**微信小程序 + 中文食材库 + 拍照识别 + 临期推送**存在差异化空间。
- KeepFresh 的差异化应聚焦：**极低录入成本（一次快门）+ 识别失败手动兜底 + 临期→菜谱的强引导闭环**，而非堆功能。

## D. KeepFresh 产品机会与功能优先级（基于竞品）

| 机会 | 依据 | 优先级 |
|------|------|------|
| 识别失败/无密钥时的手动兜底必须顺滑 | 三星/LG/薄荷均依赖识别，失败即阻断；KeepFresh 已有 Mock+手动，需强化 UX | P0 |
| 临期→菜谱强引导闭环 | 竞品多"记了但不推怎么吃"；KeepFresh `recommend.ts` 已支持临期优先 | P0 |
| 微信订阅消息真正触达临期提醒 | FridgePal 有提醒但非微信；KeepFresh 未接入推送 | P1 |
| 中文食材别名归一 | 竞品少提；KeepFresh `food-database.aliases` 已建但未用于菜谱匹配（R06 缺陷） | P1 |
| 低录入成本（拍照/小票） | FridgePal 小票、薄荷拍照均验证该价值 | P1 |
| 家庭多成员共享库存 | 竞品多单人；可作为差异化（待验证 C） | P2 |

## C. 基于用户截图的竞品观察（冰箱鲜存记 / 鲜时记）

> 说明：本环境无法解析用户提供的竞品截图（图像通道不可用）。以下仅依据用户在需求书（§二）中复述的界面特征整理，**未引用任何后台数据、用户评价、市场份额或未经证实的功能**，仅作设计观察，不构成事实断言。

### C.1 冰箱鲜存记（竞品 A，设计观察）

| 观察维度 | 所见设计特征 |
|----------|--------------|
| 首页 | 清晰任务入口，突出"拍照入库""生成菜单"两个核心动作 |
| 库存 | 支持分类筛选，并**区分不同食材批次**（与 FreshKeep 批次模型一致） |
| 菜单推荐 | 强调"优先处理临期食材" |

### C.3 对 FreshKeep 的差异化启发（本人判断）

- FreshKeep 已具备：批次独立、规则保鲜、菜谱规则推荐、可插拔识别——与两者核心一致。
- 可借鉴（列入 P1/P2，非本轮实现）：入库表单补"生产日期/保质期"字段（鲜时记）、库存增加"状态/位置"筛选（鲜时记）、个人中心补"浪费复盘/隐私说明"（鲜时记）、首页强化"优先处理临期"引导（冰箱鲜存记）。
- 不复制：品牌文案、插画、Logo、专属视觉资产；不声称竞品未展示的功能存在或不存在。
