# 需求优先级与迭代计划（Iteration Backlog）

> 日期：2026-10-19 ｜ 依据：代码审查 + 真实测试（D1–D6）+ 竞品调研 + 用户研究（待补）
> 优先级：P0（阻塞体验/安全）> P1（准确性/一致性）> P2（体验增强）
> 原则：**不虚构"将提升 X%"**，只给可验证的预期指标与验收标准。

---

## P0

### P0-1 临期提醒真正触达用户（接微信订阅消息）
- 用户问题：提醒只在逻辑层生成，用户根本收不到，闭环断裂。
- 证据来源：test_plan D6；analytics_spec `expiry_reminder_*` 未接入。
- 影响范围：留存、减浪费核心价值。
- 解决方案：申请订阅消息模板 → scan/首页触发授权 → 服务端/云函数定时推送 urgent/soon 食材。
- 实现成本：中（需小程序订阅消息资质 + 定时任务）。
- 预期验证指标：订阅授权率、提醒点击率（`expiry_reminder_clicked/shown`）。
- 验收标准：真机收到至少 1 次临期推送且可点击进入对应食材。

### P0-2 识别失败/无密钥时的手动兜底强化
- 用户问题：无密钥或识别失败时，用户易卡死。
- 证据来源：scan.ts 已有 Mock+手动入口；竞品分析指出"失败即阻断"是通病。
- 影响范围：首次体验。
- 解决方案：识别失败统一兜底页（手动输入 + 拍照重试 + 示例引导），明确"演示模式"标识。
- 实现成本：低。
- 预期验证指标：识别失败场景下任务1完成率（用户研究）。
- 验收标准：无密钥/失败时可 100% 走通手动录入。

## P1

### P1-1 编辑购买日期重算最佳食用期 【✅ 已完成 · 已回归】
- 用户问题：改了购买日期，最佳食用期不变，临期判断失真。
- 证据来源：测试 S13 失败（缺陷 D1）。
- 影响范围：保鲜计算准确性。
- 解决方案：`updateIngredient` 在 patch 含 `purchaseDate` 时按 `calcBestBeforeFix` 重算 `bestBeforeDate`。
- 实现成本：低。
- 验收标准：✅ 重跑测试 S13 通过（保鲜回归 20/20）。

### P1-2 编辑保存方式同步分区 【✅ 已完成 · 已回归】
- 用户问题：冷藏改冷冻，分区仍显示旧区，信息矛盾。
- 证据来源：测试 S14 失败（缺陷 D2）。
- 影响范围：库存展示准确性。
- 解决方案：`updateIngredient` 在 patch 含 `storageMethod` 时调 `defaultAreaForMethod` 重算 `storageArea`。
- 实现成本：低。
- 验收标准：✅ 重跑测试 S14 通过（保鲜回归 20/20）。

### P1-3 菜谱匹配归一食材别名 【✅ 已完成 · 已回归】
- 用户问题：库存写"番茄"，菜谱匹配不到"西红柿"，推荐漏荐。
- 证据来源：测试 R06 失败（缺陷 D3）。
- 影响范围：推荐相关性。
- 解决方案：匹配前用 `findFood(name)?.name` 归一为标准名再比对 `RECIPE_DATABASE`。
- 实现成本：低。
- 验收标准：✅ 重跑测试 R06 通过（菜谱回归 20/20）；可继续扩充别名覆盖。

### P1-4 后端代理转发百度调用（密钥安全）
- 用户问题：Secret Key 落前端有泄露风险。
- 证据来源：README 凭证安全；历史密钥已移除待轮换。
- 影响范围：安全合规。
- 解决方案：云函数持有密钥，小程序传图→代理调百度→返回结果。
- 实现成本：中。
- 验收标准：前端无 Secret；端到端识别链路跑通（接 P0-2 兜底）。

## P2

### P2-1 批次独立性（原"D4 去重"已撤销）【↩️ 非缺陷】
- 用户问题：旧判为"重复录入产生多条"，但批次模型要求同名不同批次独立。
- 证据来源：审计 `optimization_audit.md` + 测试 S16/S21/S22。
- 结论：撤销合并逻辑；`addIngredient` 改为每次入库=独立批次（id 唯一），UI 按名称聚合展示。
- 验证：S16（两批独立）、S21（编辑 A 不影响 B）、S22（消耗 A 不影响 B）全部通过。

### P2-2 多食材同框识别
- 用户问题：一盘菜只识别 Top-1。
- 证据来源：test_plan D5；百度 dish 返回多结果待解析。
- 解决方案：解析返回 Top-N / 多图裁剪识别（需密钥）。
- 实现成本：中。验收：识别测试集多食材同框用例通过。

### P2-3 家庭多成员共享库存
- 用户问题：单人库存，家庭场景弱。
- 证据来源：竞品差异化机会（本人判断 C）。
- 解决方案：账户体系 + 共享冰箱（需后端）。
- 实现成本：高。验收：2 人共享库存读写一致。

## 排序依据小结
- P0 解决"能不能真正用起来"（触达 + 兜底）——体验与安全底线。
- P1 解决"算得准不准、信息一不一致"——准确性与一致性，已有测试直接证明缺口。
- P2 为体验增强与差异化，成本/风险更高，排在验证之后。
> 所有项均不含"预计提升 X%"的虚构承诺；指标待真实数据回填。
