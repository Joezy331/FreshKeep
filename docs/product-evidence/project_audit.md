# 项目现状与证据盘点（Project Audit）

> 项目：KeepFresh / FreshKeep · AI 智能冰箱管家（微信小程序）
> 盘点日期：2026-10-19

## 0. 一句话结论

代码层面，FreshKeep 已实现一个**可运行的 MVP 闭环**：拍照/手动录入 → 保存建议 → 库存管理 → 临期计算 → 菜谱推荐 → 消耗扣减，核心逻辑均已编码并通过真实单元测试（保鲜/临期 20 例、菜谱 20 例）。**百度智能云菜品识别的调用代码是真实存在的**（`pages/scan/scan.ts` 含完整 OAuth + `/rest/2.0/image-classify/v2/dish` 调用），但端到端未跑通（本机无可用密钥，密钥已移除待轮换），演示默认走本地 Mock。

诚实边界：**菜谱推荐是规则匹配，不是大模型生成**；**保存建议是规则库（28 种食材），不是 AI**；**临期提醒仅生成数据，未接入微信订阅消息真正触达**；**埋点仅写本地，未上报服务端/看板**；**无任何真实用户数据**。

## 2. 关键事实澄清（避免简历踩坑）

1. **"已接入百度智能云"** —— 真实调用代码存在 ✅，但**本次未以真实密钥端到端执行**，演示默认走 Mock。简历可写"已集成百度智能云菜品识别 API（OAuth + 菜品识别），并设计 Mock/LLM 可插拔兜底"，不要写"识别准确率 XX%"。
2. **"AI 食谱推荐"** —— 实为 `recommend.ts` 的**规则匹配**（匹配度评分 + 临期权重），**非大模型生成**。简历务必写"规则匹配/启发式推荐"，否则面试被追问会露馅。
3. **"AI 保存建议"** —— 实为 `food-database.ts` 的**规则库**（28 种食材的保存方式/分区/天数），非模型推理。写"基于食材知识库的保存建议"即可。
4. **"临期提醒"** —— 逻辑层生成提醒数据 ✅，但**未接入微信订阅消息**，未验证真正触达用户。写"设计了临期提醒策略与触发逻辑"更准确。
5. **密钥安全红线** —— 仓库不含任何真实密钥；历史硬编码密钥已移出，但**须到百度/OpenRouter 控制台轮换**。生产环境务必改后端代理。
